\section{STRIDE Analysis}\label{sec:stride-analysis}

This section aims to further explain the threat mapping presented in Table~\ref{tab:stride-vuln-matrix}. 

\subsection{Spoofing}

\textbf{Password-only:} Password-only systems are the most vulnerable to phishing atttack, since they entirely rely on the user's better judgement, there is no origin binding, or relying on a safe third party. 

\textbf{2FA:} 2FA creates a much stronger barrier against phishing attacks, since it provides another wall of defence, in the form of a second factor. Depending on the type of this factor attackers can use different ways to bypass it mostly via adversary-in-the-middle proxies, or sim swapping.

\textbf{FIDO2/WebAuthn:} FIDO2's origin binding ensures that even if an attacker manages to phish the user, they can't redirect the user to a fake site, since the system would not accept the authentication request from a foreign RP ID.

\subsection{Tampering}

\textbf{Password-only:} Usually password only systems offer no protection against message tampering beyond TLS. If TLS is compromised or misconfigured, an attacker can modify login requests or responses.

\textbf{2FA:} 2FA TOTP systems also rely primarily on TLS for tampering protection. OTP codes can be be intercepted during transmission, for example in an AiTM relay attack (Real Time Phishing), where the attacker uses a proxy to phish the user's password and intercept the OTP code, then uses it to authenticate.

\textbf{FIDO2/WebAuthn:} Since FIDO2 is a digitally signed challenge-response system, modification to the challenge or response invalidates the signature, making it virtually tamper-proof even if TLS is compromised.

\subsection{Repudiation}

\textbf{Password-only:} There is no repudiation protection in a barebones password system, anyone with the password can authenticate and there is no way to link a particular login to a device or authenticator. Even logging can be manipulated since we can not be sure about the user's identity. 

\textbf{2FA:} 2FA can provide some repudiation protection by logging OTP usage, but these logs can modified by attackers who manage to gain high enough privileges. Proving the who performed the authentication is difficult in these systems, since cryptographic proof of which device generated the OTP code is not provided by the standard.

\textbf{FIDO2/WebAuthn:} Since the private keys are stored on the authenticator, and these encapsulated systems manage them FIDO2 offers strong repudiation protection, because other devices can not copy this information. The signature counter also helps detect credential cloning attempts.

\subsection{Information Disclosure}

\textbf{Password-only:} Password systems are highly vulnerable to information disclosure. Passwords are stored as hashes, but breaches can expose these hashes for offline cracking. More critically, passwords are transmitted during every login, creating multiple opportunities for interception. Password reuse across sites amplifies the impact of any single breach.

\textbf{2FA:} TOTP reduces information disclosure risk compared to passwords. The TOTP secret is stored server-side and never transmitted, but if compromised, it can generate valid codes. OTP codes themselves are short-lived but can be intercepted during transmission. Backup codes, if stored improperly, can also be a disclosure risk.

\textbf{FIDO2/WebAuthn:} One of the main principles of FIDO2 is that shared secrets are transmitted only public keys are stored server-side, and private keys never leave the authenticator. Even in an event of databreach the attacker can only get the public keys, which are not enough to authenticate.

\subsection{Denial of Service}

\textbf{Password-only:} There are multiple DoS attack vectors for password systems, and bad actor might use bruteforce, to overwhelm the server, but there are certain types that focus on attacking a single user via the server's security features like lockout mechanisms. An attacker might trigger lockouts by repeatedly attempting incorrect passwords, preventing legitimate users from accessing their accounts. Authentication systems usually implement countermeasures, like rate limiting, but these are not always effective.

\textbf{2FA:} 2FA systems inherit the vulnerability of password-only systems, the lockout mechanism may shift to the OTP code level, but the attackers can also exhaust backup codes, flood users with OTP requests.

\textbf{FIDO2/WebAuthn:} Passwordless authentication is resiliant to DoS attacks, its biggest vulnerability is the hardware doing the authentication, like wiping data from the authenticator in a CTRAPS attack, which factory rests private keys. On the server side there is no incentive to penalise user with lockouts, since there is no passwrod for the attackers to guess.

\subsection{Elevation of Privilege}

\textbf{Password-only:} Since administrative accounts without the proper precaution can fall victim to a multitude of attacks, bad actors can gain initial access to administrative accounts and elevate their privileges.

\textbf{2FA:} 2FA and password only systems are similarly vulnerable to privilege elevation attacks, even though the additional factor makes them more difficult, with the proper safety measures in place seemingly impossible for attackers to gain access, the elevation of privilege is still possible with the aforementioned techniques

\textbf{FIDO2/WebAuthn:} For FIDO2 elevation of privilege attacks do not usually target the cryptographic protocol, but they may try to register their FIDO keys to a high privilege account, granting them access to rights they should not have.
