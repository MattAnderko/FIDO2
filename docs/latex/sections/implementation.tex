\section{Implementation}\label{sec:implementation}
This section talks about the components of, and how they interact in the prototype, that we will run our STRIDE testing and performance analysis on, we will also talk about the packages used in the backend, this is important to reflect on in when evaluating the results. 

\subsection{Backend Packages}
We use the backend packages, listed in Table~\ref{tab:backend-packages}. Python's FastAPI framework handles requests, while `pydantic` ensures data integrity. For our database we use PostgreSQL (via `psycopg2-binary`) as it is FOSS and is widely used in the industry, to link our database to our application we use `sqlalchemy`, which serves as an ORM layer, so we can interact with the database in a type-safe way. The package `redis`stores state objects, like WebAuthn challenges. Session management is done by `pyjwt` package, it has the job of issuing JSON Web Tokens upon successful login.

We implement different authentication methods:
\begin{itemize}
    \item \textbf{Password}:  For hashing the user's password we use the `bcrypt` library, configured with a work factor of 12 salt rounds to align with OWASP recommendations~\cite{OWASPPasswordStorage}, according to the guidelines, this should ensure that stored credentials remain resistant to rainbow table and brute-force attacks while maintaining acceptable server performance (200ms).
    \item \textbf{2FA (TOTP)}: Besides the password management we also had to implement a 2FA system, using the Time-based One-Time Password algorithm. We chose the `pyotp` library, supported by `qrcode` for provisioning, we follow RFC 6238~\cite{RFC6238} during the implementation, we used HMAC-SHA1 based OTP, requiring a 6 digit code.
    \item \textbf{FIDO2/WebAuthn}: For credential registration and authentication we use the  official `fido2` library with `cbor2` for binary data decoding.
\end{itemize}
